### Grok (on X)

**The structure of the messages I receive is as follows:**

### Overall Input Structure
I receive a single, large, concatenated prompt that always follows this general layout (in this exact order):

1. **System / Instructions block** (plain text + markdown)
   - Starts with: `"You are Grok, built by xAI."`
   - Followed by a long list of behavioral rules, restrictions, capabilities, and principles (all in bullet points and paragraphs).
   - This block is always present and is the first thing in the prompt.

2. **Tool definitions section**
   - Header: `## Available Tools:`
   - Then a series of JSON-style objects (one per tool), each looking like this:

```json
{"name": "code_execution", 
 "description": "Execute Python 3.12.3 code via a stateful REPL.\n- Pre-installed libraries:\n...", 
 "parameters": {"properties": {...}, "required": [...]}}
```

   - All available tools are defined this way, in plain JSON format (not wrapped in extra XML or outer JSON).

3. **Render components section**
   - Header: `## Available Render Components:`
   - Then a numbered list describing each render component (`Render Inline Citation`, `Render Searched Image`, etc.), including their descriptions, types, and argument schemas. This is written in markdown with bold headings and bullet points.

4. **Optional conversation history** (only present in ongoing chats)
   - Previous turns are usually included in a simple format such as:
     - `Human: [previous user message]`
     - `Assistant: [previous response]`
   - Or sometimes just appended as raw previous messages. This section is not always present (e.g., on the very first message of a conversation).

5. **Current time** (sometimes present)
   - A line like: `Current time: Thursday, June 18, 2026 02:33 AM UTC`

6. **Current user question**
   - Always ends with:
     ```
     Current user question:
     [Your exact message here, with no extra wrappers]
     ```

### Key Points About the Format

- **No XML tags** around the user message itself. Your message arrives as raw plain text after the "Current user question:" label.
- **No JSON wrapper** around your message. It is not inside a `{"role": "user", "content": "..."}` object or similar.
- **Tool definitions** are provided as raw JSON objects (as shown above).
- **System instructions** are plain text/markdown (no special tags).
- **My tool calls** (when I output them) use a specific XML-inspired format:
  ```xml
  invoke tool example_tool_name with example_arg_name1 is example_arg_value1 example_arg_name2 is example_arg_value2
  ```
  But that is for *my output*, not for messages I receive.

- **Render components** are also only in *my output* (using special render tags in the final response). They do not appear in the input I receive.

### Summary
You (the user) send a normal plain-text message.  
What I actually "see" is that plain-text message prefixed by a very long, structured system prompt that contains:
- My core instructions,
- Tool schemas in JSON,
- Render component descriptions,
- And (when relevant) conversation history.

There are no additional layers like outer JSON objects, XML envelopes, or role tags wrapping *your* message. The structure is mostly a big block of instructions + JSON tool definitions + your raw question at the end.

**Typical structure**

A chat request is usually a sequence of messages with roles like system, developer, user, assistant, and sometimes tool. The system message is generally first and has the highest-level instructions, while developer messages add application-specific rules before the user's message appears.[[learn.microsoft](https://learn.microsoft.com/en-us/azure/ai-foundry/openai/concepts/advanced-prompt-engineering?view=foundry-classic)]

**Literal-style format**

In a model-spec-style representation, it can look roughly like this:

xml

<system>

  ...

</system>

<developer>

  ...

</developer>

<user>

  Your message here.

</user>

That XML-like styling is a common **representation** of the message flow, even when the actual transport format is JSON or another API schema.[[deepwiki](https://deepwiki.com/openai/model_spec/2.2-message-structure)]

**What comes before your message**

Before your message, there may be:

-   System instructions about behavior, safety, and priorities.[[learn.microsoft](https://learn.microsoft.com/en-us/azure/ai-foundry/openai/concepts/advanced-prompt-engineering?view=foundry-classic)]
-   Developer instructions about how the app should behave and which tools are available.[[deepwiki](https://deepwiki.com/openai/model_spec/2.2-message-structure)]
-   Tool definitions or tool schemas that tell the assistant what functions it can call.[[deepwiki](https://deepwiki.com/openai/model_spec/2.2-message-structure)]

In this conversation, your visible message is preceded by background and instruction layers, not just your text alone.
